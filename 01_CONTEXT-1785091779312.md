## 1. What this product is

**AcadeGrade** — AI-powered CGPA and academic performance tracker for Nigerian
university students (Nigerian 5-point grading scale). Currently a Next.js 16
web app (App Router) with three route groups:

- `(public)` — marketing, calculator, login/register — **stays web-only**
- `(admin)` — platform admin console — **stays web-only**
- `(student)` — the authenticated student experience — **this is what we're
  building as a native mobile app**

The mobile app is **student-only**. No admin functionality. Admin and public
marketing remain the web app's job forever.

## 2. Existing tech stack (web)

Next.js 16.2.9 · React 19.2.7 · Tailwind CSS v4 · Firebase (Auth, Firestore,
Realtime Database, Cloud Messaging, Admin SDK) · Groq/Gemini/DeepSeek for AI
features · `simple-statistics` for forecasting · `jspdf` for transcript PDFs
(web-only, mobile will call the existing PDF API instead) · Cloudinary for
avatar uploads · Nodemailer for email.

## 3. Target mobile stack

- **Expo (React Native) + Expo Router** — file-based routing, matches the
  mental model of the existing Next.js App Router
- **NativeWind v4** — Tailwind syntax on RN, lets us port `globals.css` design
  tokens directly instead of re-deriving a new theme
- **React Native Reanimated + Gesture Handler** — all animations and gestures
- **react-native-svg** — for CGPAArc, charts, radial progress (replaces web SVG)
- **@react-native-firebase/app, /auth, /firestore, /messaging** — native
  Firebase modules (NOT the `firebase/*` web SDK — it does not persist auth
  sessions or handle push reliably on RN)
- **Zustand** — lightweight client state (mirrors what Context/hooks do on web)
- **TanStack Query** — server state/caching for API route calls
- **Lottie (`lottie-react-native`)** — celebratory/success micro-animations
  (e.g. degree class upgrade, CGPA milestone)
- **expo-sharing / expo-file-system** — replaces Web Share API + client PDF gen

## 4. Backend — do not rebuild this

The mobile app talks to the **same production API routes** the web app already
uses. Authentication is via Firebase ID token in the `Authorization` header —
same pattern the API routes already expect. Relevant routes:

| Route | Purpose |
|---|---|
| `POST /api/auth/otp/send`, `/verify` | OTP flow |
| `POST /api/auth/password/reset` | Password reset |
| `POST /api/results/extract` | AI OCR of result slip photo → parsed courses (Gemini multimodal) |
| `POST /api/ai/insights`, `/forecast`, `/whatif` | AI academic insights (12h cooldown enforced server-side) |
| `POST /api/transcript/generate` | Returns generated PDF — mobile just downloads/shares it, does NOT generate PDF client-side |
| `POST /api/transcript/share` | Public share link creation |
| `POST /api/notifications/send` | Push (server calls this; mobile just registers its token) |
| `DELETE /api/user/fcm-token`, `/api/user/delete-account` | Account/session management |

## 5. Data model (Firestore/RTDB) — unchanged

- `users/{uid}` — profile, settings, `fcmTokens: string[]` (array — supports
  multiple simultaneous devices; append on login, remove specific token on
  logout, prune dead tokens on send failure)
- Semesters/courses subcollections per the shapes in `types/course.ts`,
  `types/semester.ts`
- RTDB used specifically for low-latency notification unread counts

## 6. Grading rules (must match exactly)

Nigerian 5-point scale: A(70–100)=5, B(60–69)=4, C(50–59)=3, D(45–49)=2,
E(40–44)=1, F(0–39)=0.

Degree classes: First (4.5–5.0) · 2:1 (3.5–4.49) · 2:2 (2.4–3.49) ·
Third (1.5–2.39) · Pass (below 1.5, exact lower bound per `lib/utils/constants.ts`).

Both **CGPA** (official) and **PI / Performance Index** ("True Mastery") are
tracked in parallel — the user can toggle which is primary. Don't drop PI.

## 7. Auth realities on mobile (differs from web)

- Web uses `signInWithPopup` for Google — **does not work on RN**. Use
  `@react-native-google-signin/google-signin` + Firebase native credential
  exchange, or Expo `AuthSession`.
- Session persistence must use `@react-native-firebase/auth`'s native
  persistence — do not attempt to port the web SDK's `onAuthStateChanged`
  pattern verbatim; the concept is the same, the implementation differs.
- FCM device tokens come from `@react-native-firebase/messaging` — different
  token format from web push, but slot into the exact same `fcmTokens` array
  and the exact same append/remove/prune backend logic already in production.

**Key takeaway for the agent**: every server-side-only key above (Firebase
Admin, email, all AI provider keys) stays exactly where it is — inside the
existing Next.js API routes. The mobile app never sees these. It only ever
needs the `NEXT_PUBLIC_FIREBASE_*` equivalents (renamed to `EXPO_PUBLIC_*`)
for direct Firebase client/native-SDK access, plus `CLOUDINARY_CLOUD_NAME` if
doing direct unsigned uploads the same way web does.

## 9. What does NOT get rebuilt on mobile

- Anything under `(admin)` — never
- Anything under `(public)` — marketing/calculator/login-register pages stay
  web (mobile has its own native login screen instead, hitting the same auth backend)
- Client-side PDF generation — call `/api/transcript/generate` instead
- Three.js decorative backgrounds (`KnowledgeCoreBackground`, `OrbitingTechStack`)
  — skip entirely on mobile, they're desktop decoration, not functional UI, and
  are battery-expensive on native
